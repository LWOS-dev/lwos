# 90 — 总路线

各模块互相依赖，所以不按模块一个一个做完，而是**按阶段交错推进**。
每个阶段只挑各模块里"前置已经满足"的几个里程碑，阶段结束时手上一定有能跑的东西。

## 阶段

| 阶段 | 里程碑 | 为什么排在这里 | 阶段结束时能看到 |
|---|---|---|---|
| **P1** | GUI G0–G1；PCI E1–E2 | 几乎零依赖，趁着想做 GUI 的劲头先起个头 | 屏幕上有字；`pl` 列出 PCI 设备 |
| **P2** | resman R0–R2 | **枢纽**：之后所有东西都要从它拿内存。loader 的 attach 要一起改（见 50） | `mm` 显示内存；分配/释放正确 |
| **P3** | LWP X0–X3；GUI G2 | X2 只需要 LOADER 的 LOAD 命令，不需要 FS 或网络；G2 需要 R2 的 5MB | 同一个 LWP 在两个地址都能跑；移动方块不闪 |
| **P4** | 网络 N1–N5（QEMU，82540EM）；resman R3–R4 | 打通"宿主 make → 网线推送 → 目标机运行"这条迭代链 | `lwft run hello.lwp` 在模拟器里跑起来 |
| **P5** | 82567LM M1–M4（真机） | 模拟器上的收发环已经调稳，真机只调差异 | 真机上不重启就能跑新程序 |
| **P6** | DLL L1–L3 | 有了快速迭代链，DLL 可以在真机上反复试 | GFX.DLL 可用 |
| **P7** | 任务 T0–T6 | 最后动，因为它改变所有既有代码的前提 | 抢占式多任务，FPU 正确 |
| **P8** | GUI G3–G7；文本控制台 C0–C4 | GHOST 文本窗口、任务资源传递、CRT 与 stdio | 多窗口桌面；普通 main + printf 的 Hello World |
| **P9** | AHCI A1–A5；块设备/FS B1–B4 | PIO 现在能用，AHCI 不急。**例外见下** | 运行时能读写磁盘文件 |

**P9 的例外**：如果真机的 BIOS 不能把 SATA 设成 IDE 兼容模式，PIO 就看不到盘，
LOADER 也启动不了。这种情况下 AHCI 要提前到 P2 之后，而且 loader 也得支持 AHCI。
先在真机 BIOS 设置里确认这一点。

**GUI 和 PCI 不需要按顺序做**：P1 里两件事互不依赖，哪个有灵感先做哪个。

## 每次停下时：写一条日志

在 [99-log.md](99-log.md) 最上面追加一条（新的在上，旧的不删）。三段，每段一两行就够：

```
## 2026-10-03  P1 / G1

- 做到：font8x16.c 生成好了，draw_text 能画 ASCII，g1 命令可用
- 下一步：G2 后备缓冲；先决定 5MB 从哪来（R2 还没做，临时写死 0x800000）
- 坑：BIOS 字体表的 ES:BP 是实模式段:偏移，要换算成 seg*16+off
```

回来时的顺序：

1. 读 99-log.md 最上面一条。
2. 跑一下"做到"里提到的 demo，确认它还能跑。
3. 打开"下一步"指向的那篇 spec，从对应里程碑继续。

做完一个里程碑时，顺手把那篇 spec 里的"现状"一节改掉。
