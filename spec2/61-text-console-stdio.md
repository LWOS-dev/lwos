# 61 — GHOST 文本窗口与 C 标准输出

## 目标

让普通 C 程序通过项目提供的 `stdio.h` 和最小运行库，在 GHOST（GUI host）的文本窗口里输出。
应用只需编写类似常见控制台项目的 Hello World：

```c
#include <stdio.h>

int main(void)
{
    printf("Hello, world!\n");
    return 0;
}
```

构建系统负责链接启动代码、标准输出实现，并给 LWP EXE 标记文本窗口需求。
用户启动程序后，GHOST 显示一个 80×25 字符的窗口；程序退出后保留输出和退出状态，直到用户关闭窗口。
这里要求的是类似 MSVC 控制台 Hello World 的源码使用体验；产物仍为本项目的 LWP，
不要求兼容 Windows PE、MSVC CRT 或完整 ISO C 标准库。

## 现状

截至 2026-10-21，工作区已有以下基础，但尚未完成本篇闭环：

- `lib/include/lwp.h` 已定义 `LWP_FLAG_NWIN = 0x08`、`LWP_FLAG_TEXT = 0x10`、`LWP_FLAG_GFX = 0x20`。
- `lib/include/resman.h` 已有 `LW_BUF_TXT`、`LW_VI` 和 `LW_ENV.vi`，可传递文本缓冲区描述符。
- `app/resman/src/image.c:resman_image_load` 已保存映像 flags，尚未根据 TEXT 建立文本窗口资源。
- 外部程序目前显式使用 `lwp_main(const LW_ENV *)`；本篇提出的自动绑定 stdout 和普通 main 启动链仍待实现。

以下接口语义与里程碑属于设计要求；新增接口名称和 slot 在实现时确定。

## 设计

### 职责与数据路径

```text
C 源码 main + printf
    → 项目 CRT / stdio / 格式化器
    → 本任务的文本输出后端
    → resman 持有的 80×25 字符缓冲区
    → GHOST 读取字符、颜色和光标状态
    → 字体绘制、窗口合成
    → framebuffer
```

- **resman**：解释 EXE 需求，分配文本对象，维护窗口注册、任务关联和资源生命周期。
- **应用运行库**：绑定本程序的 stdout，负责字符写入、换行、光标推进和滚屏。
- **GHOST**：管理窗口位置、标题栏、遮挡和焦点，将字符绘制成像素；不解释 printf 格式串。
- 应用不需要访问 framebuffer、`0xB8000` 或 GHOST 内部窗口结构。
- 文本缓冲区是字符单元数组，framebuffer 是像素数组，两者不能混为同一块内存。

### EXE 标志与启动事务

沿用现有标志值：NWIN 为 bit3，TEXT 为 bit4，GFX 为 bit5。三者互斥；
全部未设置时保留旧程序的 LEGACY 行为，不能自动把旧图形程序归类为文本程序。
组合冲突必须在分配资源前拒绝。DLL 不通过这些标志自动建立窗口。

mkexe 应支持显式选择文本模式，标准控制台构建目标默认选择 TEXT；具体命令行拼写在实现时确定。
工具只记录构建声明，不通过扫描 printf 符号或源代码猜测窗口需求。

加载/任务创建流水线必须在应用进入 READY、可能执行入口之前完成：

1. 校验 flags、运行环境支持及映像格式。
2. 分配映像、栈、文本对象和字符缓冲区，初始化窗口记录。
3. 创建任务的持久 `LW_ENV`，填写 `vi.size`、`vi.mode = LW_VI_TEXT`、`vi.window_id`、`vi.txt`。
4. 将窗口发布给 GHOST，再允许应用执行。发布前，GHOST 不得看到半初始化对象。
5. 任一步失败，撤销窗口记录并释放本次创建的资源，向启动者返回明确错误。

没有可用 GUI host 或暂不支持该模式的启动路径必须明确失败，不能静默回退到物理文本显存。
GHOST 不能同步调用应用并等待其返回；应用即使持续计算，GHOST 也必须能继续刷新。

### 文本对象与环境传递

第一版固定 80 列、25 行，共 2000 个 WORD（4000 字节有效内容）：

- 索引为 `row * cols + col`；低 8 位字符，高 8 位颜色属性。
- 属性低四位为前景色，高四位为背景色；第一版使用固定 16 色表，不实现闪烁位。
- 初始填充 `0x0720`，即灰字、黑底、空格；第一版保证 ASCII 可打印字符。
- 使用 8×16 字体时，窗口客户区为 640×400 像素，标题栏和边框另计。

沿用 `LW_BUF_TXT { cols, lines, buffer }`。`env->vi.txt` 指向持久描述符，
`txt->buffer` 指向该任务独享的字符数组。应用可写数组，但不得释放它或改变描述符中的地址、尺寸。
环境和描述符不能放在加载函数返回后失效的栈上。

当前平坦共享地址空间允许应用和 GHOST 访问同一对象；这是访问约定，不是内存隔离。
GHOST 通过 resman 的窗口枚举/获取接口取得对象，不扫描应用内存或依赖固定地址。
每个窗口至少关联窗口 ID、任务身份、文本描述符、生命周期状态和退出码。
光标行列、可见性及更新状态作为附属元数据维护；若扩展公开结构，必须同步规定 size/version 的兼容检查。

### 刷新与并发

首个闭环允许 GHOST 在自己的刷新循环中定期重绘文本窗口，不要求应用主动调用 present。
这样一次 printf 之后即使应用进入等待，输出也能被看见。
后续可增加更新序号/脏行通知，避免不必要的重绘，但不能改变 printf 的使用方式。

第一版允许刷新碰上字符写入或滚屏而看到一次中间画面，下一帧应收敛；不承诺整次 printf 原子显示。
窗口表发布、获取和撤销必须同步，GHOST 持有有效引用期间对象不可释放。
只在短临界区保护元数据；不在关中断状态下格式化字符串或绘制整个窗口。
同一窗口暂定单个应用写入，不提前引入多个写者或跨任务 stdout 共享。

### CRT 与 stdio 分层

保留 LWP 的 `lwp_main(const LW_ENV *)` 为加载入口；控制台程序由 CRT 提供该函数：

1. 校验环境和文本能力，保存本 EXE 的 ABI/resman 表地址。
2. 将 stdout 绑定到 `env->vi.txt` 对应的文本输出后端，初始化输出状态。
3. 调用用户的 main，支持 `int main(void)` 和 `int main(int argc, char **argv)` 的常规源码形式。
4. 在正常返回时完成运行库清理/刷新，将 main 返回值交给既有任务退出路径。

入口适配、调用约定及 argv 生命周期须由工具链统一实现；应用不手写环境绑定。
第一版将 CRT、stdio 和格式化器静态链接进每个 EXE，使各程序的 stdout、光标和工作状态互不串扰。
应用不能同时链接 CRT 提供的入口和自己定义的 lwp_main；构建时应诊断重复入口。

项目提供 `stdio.h` 及所需的 `stdarg.h`/类型支持，先实现以下子集：

| 接口 | 职责与首版约定 |
|---|---|
| `vsnprintf` / `snprintf` | 有界内存格式化；返回未截断时所需字符数，不含结尾 NUL；size > 0 时写入 NUL；允许 size = 0 的长度查询 |
| `vsprintf` / `sprintf` | 向调用者提供的足够大缓冲区格式化；不具备容量保护，运行库内部优先使用有界路径 |
| `vprintf` / `printf` | 格式化后送到本任务 stdout；成功返回输出字符数，失败返回负值 |
| `putchar` / `puts` | 写单字符/字符串；puts 追加换行；错误返回 EOF，成功遵循各自接口约定 |

格式化核心只处理字符输出，不依赖 GHOST 或屏幕；建议以字符输出回调复用字符串和控制台后端。
printf 不得通过无界 vsprintf 写入固定大小的临时数组；可直接流式输出或使用受限分块。
第一版 stdout 无缓冲，main 返回无需等待 GUI 实际呈现；文本对象的保留保证最终内容仍可显示。

首版格式集合：`%%`、`%c`、`%s`、`%d`/`%i`、`%u`、`%x`/`%X`、`%p`，
支持常量字段宽度、左对齐 `-` 和整数补零 `0`。具体指针表示固定为带 `0x` 前缀的八位十六进制。
长度修饰符、精度、动态宽度、浮点、`%n`、宽字符和 locale 后续再扩展；
不支持或不完整的格式必须返回错误，不能用错误的类型读取变参。
实现须覆盖 INT_MIN 和无符号边界，不借用宿主 libc 的运行时实现。

文本输出后端处理 `\n`（下一行首列）、`\r`（回到本行首列）、`\t`（以空格推进至下一个 8 列制表位）。
普通字符写完末列后换行；越过第 25 行时上滚一行，并用当前属性的空格清空底行。
`printf` 的返回值计入输入的换行/制表字符本身，不按展开后的空格或屏幕格数量计数。
首版不解析 ANSI 转义序列，不实现通用 FILE、文件 I/O 或 stdin。

### 退出、窗口关闭与资源回收

文本对象由 resman 管理，不能仅登记为会在 task reap 时无条件释放的应用堆分配。
任务结束后记录退出码并冻结应用写入，GHOST 保留窗口内容，标题可显示已退出状态。
任务映像和栈可以回收；文本对象由窗口继续持有，不能依赖已回收的 LW_ENV、argv 或应用字符串。

用户关闭已退出窗口后，撤销窗口记录，待 GHOST 的读取引用释放后再释放文本对象。
首版关闭活任务窗口应走已有终止任务流程，确认任务不再写入后再撤销窗口和回收资源。
窗口身份须有代次或等效失效机制，不能因任务槽/窗口槽复用，把旧窗口关联到新任务。
GHOST 正常退出也必须清理或移交注册窗口，不留下悬空读取者；异常恢复策略另行设计。

不能只依靠宿主格式化测试代替完整链路。

## 待决

- resman 窗口查询、获取/释放引用、状态通知的最终 ABI 名称与 slot 分配。
- 光标附属元数据的公开布局；更新序号与批量输出同步策略。
- 后续焦点输入队列、stdin 行编辑、shell、重定向及输出历史；80×25 可见缓冲区本身不等于终端历史。
- UTF-8、中文字体、窗口尺寸调整、完整 printf 格式和文件流支持，按独立里程碑扩展。
