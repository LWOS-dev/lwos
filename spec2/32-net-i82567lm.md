# 32 — 82567LM（8086:10F5，真机）

## 型号确认

**8086:10F5 是 "82567LM Gigabit Network Connection"**，确实是有线千兆网卡。
它常见于 ICH9M 芯片组的笔记本（ThinkPad T400/X200 这一代）〔需查证：以你手上的机器为准〕。

名字是 **82567LM**，不是 82567M。

**它的结构和 82540EM 不一样**：82567 只是一个 **PHY 芯片**，MAC 集成在南桥（ICH9）里。
Linux 的对应驱动是 `e1000e` 里的 `ich8lan` 部分。好消息是 MAC 这一侧对软件呈现的寄存器，
和经典 e1000 大部分相同，所以 [31](31-net-i82540em.md) 调通的 `e1000_ring.c` 可以复用。

**没有模拟器模拟这个型号**，只能在真机上调。

## 目标

在真机上以 IRQ 唤醒方式收发裸以太网帧，达到 [30](30-net.md) 的 N4/N5。

## 当前接入

用户已确认真机 PCI ID 为 8086:10F5。`app/resman/src/net.c` 已加入独立的
82567LM 固件接管分支：恢复 D0、设置 PCI MMIO/Bus Master/INTx、取得 SWFLAG、
读取 PHY BMCR 并在无链路时退出 power-down/isolate、启动自动协商。
关闭收发、取得 SWFLAG 后等待 DMA 停止，执行 MAC 软件复位（PHY_RST 清零）；
先等待 20ms，再有界等待 RST 清零和 EEC.Auto_RD，之后重建环。
保留 PHY 链路/校准，由硬件重新加载 NVM，不执行 EERD 或写闪存。
接收使用 resman IRQ 队列，`netrecv FILE` 保存文件；`netrecv -d` 打印寄存器、
链路和 ICS→INTx→ISR 自检结果。

`make test-net-init` 的寄存器模型覆盖 D3→D0、锁占用、MDIO 错误/超时、
无效 MAC/IRQ、IRQ 自检失败及释放/重新打开；这不等同于真机 PHY 验证。
下面列出的完整 PHY 复位、NVM/PHY 差异仍是后续工作；先用诊断输出定位
当前真机停在哪一步。用法及输出解释见 coreutils README。

真机已确认 link-up、INTx 自检通过，PUT 可接收并创建文件；但 ACK 入队后
TDH=0、TX done=0，发送队列不推进。核对 Intel ICH SDM §10.4.58 发现，
TX 环必须至少有 16 个描述符。现已从 8 个（128 字节）改为独立的
16 个（256 字节），RX 环仍为 8 个。寄存器模型加入最小尺寸限制后，
旧实现的单 ACK 测试会失败；修正尺寸后通过，并检查 TX 回绕及队列满。
新增 TDBAH/TDBAL/TDLEN/ring 诊断。真机读回 TDLEN=256、基址正确，但
8 个 ACK 入队后仍 TDH=0、done=0。因此现改为重建环前复位 MAC 数据通路，
而不依赖单纯关闭收发保留的片内状态；真机发送结果仍待验证。
新增 CTRL_EXT/EEC/PBA/PBS 和首个 TX 描述符诊断；寄存器模型检查复位前
DMA 停止、SWFLAG 所有权、PHY_RST 清零、复位后的 20ms MMIO 静默期，
并覆盖 DMA/RST/NVM 自动加载超时与原始 DRV_LOAD 的恢复。

MAC 复位后真机 EEC=00400300，PBA=000e000a、PBS=00000018，TX0 的
cmdlen=0b00003c，但 TDH/done 仍为 0。检查发现代码又把复位后的 TCTL
清零，并用旧型号常量覆盖启用值。ICH SDM §10.4.52 中 bit28 默认置位，
RRTHRESH[30:29] 默认 01；现启停 TX 均使用读改写，保留这些高位配置，
TARC1 bit28 根据 TCTL.MULR 取反。新增 TCTL-reset/TARC1 输出。
寄存器模型补入高位复位默认值后，旧代码的保留检查会失败；修正后覆盖
MULR 的两种配置和不同 RRTHRESH，仍需真机确认 TX 是否恢复。

## 和 82540EM 的差异（这些就是 `i82567lm.c` 要写的内容）

以下每一条都要对照 Intel 文档和 Linux `drivers/net/ethernet/intel/e1000e/ich8lan.c` 核对。

| 方面 | 82540EM | 82567LM (ICH9) | 做法 |
|---|---|---|---|
| **MAC 地址来源** | EEPROM，用 EERD 读 | 在 SPI 闪存的 GbE 区域，走 BAR1 的闪存寄存器；**EERD 不能用** 〔需查证〕 | 第一版**直接读 RAL0/RAH0**：硬件复位后会自己从 NVM 把 MAC 装进去。读到全 0 或全 F 再考虑读闪存 |
| **复位前** | 直接 CTRL.RST | 要先拿软件/固件信号量：EXTCNF_CTRL（0x0F00）的 SWFLAG 位（bit5），因为管理引擎（AMT）也在用这个 MAC 〔需查证〕 | 置 SWFLAG，读回确认拿到后再复位；复位后释放 |
| **复位后** | RST 自清即可 | 要等 NVM 自动加载完成；可能还要等 PHY 复位完成 〔需查证：STATUS 里的哪一位〕 | 先多等一段时间（例如 20ms），再读 STATUS |
| **PHY** | 内部 PHY，SLU 就能起 | 外部 PHY（82567），通过 MDIC（0x0020）访问；ICH 上 PHY 访问也要拿 SWFLAG | 第一版不碰 PHY，依赖硬件自动协商。只在链路起不来时才去读 PHY 状态 |
| **AMT/管理引擎** | 无 | 可能在共享这个网口 | 如果 BIOS 里能关 AMT，调试时先关掉 |
| 描述符、收发环、RCTL/TCTL | — | 相同 | 复用 `e1000_ring.c` |

## 迭代策略

真机上每改一次都要重写磁盘、重启，所以：

1. **先在模拟器上把 `e1000_ring.c` 调稳**，真机上只调差异部分。
2. 第一版真机驱动只做一件事：**把能读到的寄存器全打印出来**（CTRL、STATUS、RAL0/RAH0、EXTCNF_CTRL），先确认读到的是合理值。
3. 然后再依次试：只收、只发、收发。
4. 宿主端用 `tcpdump -e` 抓包对照。
