# spec2 — LWOS v2 规格书

旧的 `SPEC/` 是从 v1 代码反推出来的描述，文件名、行号、函数名都指向 v1 的 `kernel/`，
和 v2 已经对不上。`spec2/` 描述的是 **v2 要走到哪里**，而不是 v1 曾经是什么样。

## 写法约定

- **不写行号**。引用代码一律写 `文件:符号`，例如 `lib/abi/src/abi.c:lw_abi`。行号一改就失效，符号名活得久。
- 每篇文档固定这几节：
  - **目标**：做完之后能干什么
  - **现状**：v2 里已经有什么（写到哪天为止）
  - **依赖**：前置（没有它做不了）/ 后继（谁在等它）
  - **设计**：数据结构、接口、文件布局
  - **里程碑**：每一步都以一个**能跑的 demo** 结束，附验收条件
  - **待决**：还没拍板的问题
- 文档里写的是**目标**，不是已完成的事实。做完一个里程碑，就把"现状"那一节更新掉。
- 标了 **〔需查证〕** 的内容来自记忆或推断，动手前要对照手册核对。

## 依赖关系总图

箭头 `A → B` 表示 "B 需要 A"。

```
                      ┌────────────── 02 横切决策 ──────────────┐
                      │   (段模型 / IDT·GDT 归属 / 轮询 / 锁)    │
                      └─────────────────────────────────────────┘

 ABI pci slots ─→ 20 PCI 枚举 ─┬─→ 21 AHCI ─→ 22 块设备 ─→ 22 运行时 FS ─┐
                               │                                          │
                               └─→ 30 netdev ─┬─→ 31 82540EM (模拟器)     │
                                              └─→ 32 82567LM (真机)       │
                                                        │                 │
 10 内存布局 ─→ 50 resman 内存 ─┬──────────────────────┤ (DMA 缓冲)      │
                                │                       ↓                 ↓
                                ├─→ 40 LWP EXE 加载 ←── 30 网络传文件 / 22 FS
                                │          │
                                │          └─→ 41 DLL
                                │
                                └─→ 51 任务 (需要 02 里的 IDT/GDT 归属先落地)
                                           │
 60 GUI G0–G2 (几乎无依赖，可以随时做) ─────┴─→ 60 GUI G3–G5 (鼠标中断、每任务窗口)
```

**关键观察**：

1. **resman 的内存分配器是枢纽**。DMA 缓冲（AHCI、网卡）、EXE 映像、任务栈、GUI 后备缓冲都要从它拿内存。它本身几乎没有前置，应该**最早做**。
2. **"EXE 从哪来"有两条路**：从磁盘（要 AHCI/PIO + 运行时 FS）或者**从网线**（要网卡 + 传文件协议）。网络这条路恰好也解决了"不停机传文件"的需求，而且跳过了 FS 写入。
3. **任务切换是最后才动的**，因为它会改变所有既有代码的前提（ABI 的静态状态要加锁、FPU 要惰性保存、IDT 要换主人）。

## 与 report/ 的关系

旧 readme 约定评审报告按章节号命名（`3x_xxx_01.txt`）。spec2 的报告建议加前缀 `s2-`
（例如 `report/s2-21_ahci_01.md`），避免和 v1 章节号撞车。
